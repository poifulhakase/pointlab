# ロボ口座 運用手順書

> 疑似トレード（ロボ口座）を毎日どう回すか。誰が何をいつやるかを時系列で書く。
> 設計の理由は `docs/robo-trade-design.md`、実装の状態は `handover.md`。

作成: 2026-08-09

---

## 0. 一番大事な前提（ここがズレると全部ズレる）

### ① ロボ口座はあなたの実際の建玉に合わせて動く

```
AIが判断 → 通知 → あなたが最終決定して実際に売買 → キャプチャを投げる
                                                      ↓
                                        ロボ口座を実際の建玉に合わせる
```

🔵 **基本的にAIの判断どおりに動く前提**なので、ロボ口座と実保有はほぼ一致する。
ズレるのは、あなたが判断でAIと違う動きをしたときだけ。そのズレを実態に合わせる。

🔴 **ただし差分は必ず記録に残る**（`divergences`）。同期しても「AIは何と言い、あなたは何をしたか」
は消さない。後から介入の効き方を追えるようにしてある。

🔴 **同期でついた売買（`exit_reason: 'sync'`）は成績に数えない。** AI の判断ではないので、
AI の実力を測る数字（勝率・期待値）に混ぜない。副次的に、読み取りの誤りが成績を汚すのも防ぐ。

### ② キャプチャは「売買した日だけ」投げる

キャプチャの有無が「売買があったか」のシグナルになる。売買していない日は投げなくてよい。

🔴 **同じ画像で二度同期しない仕組みが入っている**（file_id で判定）。
売買しない日も Chatwork には前回の画像が残っているが、それでは同期されない。

### ③ 判断は1日1回・**寄り付き前（08:30）**。執行は「その日の寄付き」として記録される

**前営業日の引け値**で判断し、記録上の約定価格は**その日の始値**として扱う。
終値で約定したことにすると、実際には取れない価格で記録され成績が良く出るため。
🔵 2026-08-10 までは前日19:30に判断していた。**使う材料も執行タイミングも同じ**で、
通知を読んでから執行するまでの間隔を縮めるための移動（詳細は「1日の流れ」）。

### ④ それでも「AIが決定論ルールより上手いか」は測り続けている

同期を入れても、対照群（決定論ルール）との比較は生きている。
30トレード後の Go/No-Go は変わらず、**期待値が対照群以上／最大DDが対照群より浅い**で判定する。

## 1. 1日の流れ

| 時刻 | 誰が | 何を |
|---|---|---|
| 15:30 | — | 東証の引け |
| **16:00** | **自動**（タスクスケジューラ） | ① チャートを撮って Chatwork へ投稿 |
| 16:00〜19:30 | **あなた** | ② **売買した日だけ**保有画面を Chatwork に投げる |
| 19:30 / 21:30 | 自動 | 需給データの取得（🔴 判断はしない） |
| **翌営業日 08:30** | **自動**（GitHub Actions） | 画像取得 → 実保有に同期 → 判断 → 記録 → 通知 |
| 翌営業日 08:35 頃 | **あなた** | Chatwork の通知を読む |
| 翌営業日 09:00 | **あなた** | 最終決定してリアル執行する／しない |

🔴 **判断は 2026-08-10 に 19:30 → 翌朝08:30 へ移した**（ユーザー判断）。
使う材料（前営業日の終値）も執行タイミング（寄り付き）も変わらないが、
**通知を読んでから執行するまでの間隔が短いほうが、読み落としも気変わりも減る**ため。
🔴 副作用＝**記録される日付が1日ずれた**。成績を日付で追うときは、この日を境に基準が
変わっていることに注意する。🔵 本番のトレードが1件も無いうちに変えたので過去の記録は混ざっていない。
🔵 判断の日に東証が休場なら走らない（＝寄り付きが無い日は判断しない）。

### あなたがやること（引け後＝**16:00**）

**① チャートを撮る**

```
npm run capture-chart
```

ローカルPCで実行。TradingView を開いて撮影し、Chatwork に自動投稿する。
🔵 **撮らなくても判断は動く**（数値だけで続行する）。PCが落ちていた日も止まらない。

🔴 **ログインは要らない**（2026-08-10 決定）。撮っているのは**公開チャート**
`https://jp.tradingview.com/chart/?symbol=INDEX%3ANKY&interval=D`。

なぜログイン方式をやめたか：
- 保存レイアウト（`/chart/ecEzo0V0/`）は**ログインしないと開けない**。
  しかも **Google は自動操作ブラウザからのログインを弾く**（`Chrome for Testing` と判定される）。
  メール＋パスワードなら入れるが、**セッションが切れるたびに毎日の記録が止まる**
- 🔴 **画像が判断に効いているかは、まだ測っていない**。効果が不明なもののために
  運用の脆さを背負うのは順序が逆
- 🔵 副産物として**銘柄のズレも解消**した。保存レイアウトは `NK1!`（SGXの先物）だったが、
  数値で渡しているのは**現物の日経225**。公開URLは現物指定なので画像と数値が揃う

🔵 **BB・MACD が欲しくなったら**、TradingView にログインして保存レイアウトを
`INDEX:NKY`（現物）に直して保存し、`.env.local` に1行足せば戻せる:
```
ROBO_CHART_URL=https://jp.tradingview.com/chart/ecEzo0V0/?symbol=INDEX%3ANKY&interval=D
```
そのときは `npm run capture-chart -- --login` で先に**メールログイン**（Googleボタンは押さない）。

🔴 **撮る時刻は 16:00 に固定する**（2026-08-10 ユーザー決定）。理由は2つ。
- 引け（15:30）の直後なので**日足が確定した状態**で撮れる
- 判断（翌朝08:30）まで時間があるので、**撮り忘れ・失敗に気づいて撮り直せる**

🔴 **精度より「毎日同じ時刻」であることが大事**。日によって時刻がずれると、
AIは違う条件のチャートを見て判断することになり、あとで成績を比べられなくなる。

🔴 **撮影は「ローカルPCで動く」ので GitHub Secrets は届かない**（2026-08-10 に踏んだ）。
Chatwork へ投稿するには、リポジトリ直下の `.env.local` に**この2行が必要**:
```
CHATWORK_API_TOKEN=...
CHATWORK_ROOM_ID=...
```
🔵 無い場合は「撮れているが投稿できない」と理由を出して止まる（分かりにくい例外で落ちない）。
🔵 判断（翌朝08:30・Actions）側は Secrets を使うので、そちらは影響を受けない。

🔵 **平日16:00は自動で走る**（2026-08-10 設定）。Windowsのタスクスケジューラに
`poirobo-capture-chart` を登録済み。手で叩く必要はない。
```
# 中身を見る／消す／今すぐ試す
Get-ScheduledTask -TaskName 'poirobo-capture-chart'
Start-ScheduledTask -TaskName 'poirobo-capture-chart'
Unregister-ScheduledTask -TaskName 'poirobo-capture-chart'
```
- 実行ログ＝`.captures/capture.log`（追記）
- 🔵 **PCが16:00に落ちていたら、次に起動したときに走る**（`StartWhenAvailable`）。
  日足の当日バーは15:30で確定し以降動かないので、遅れて撮っても中身は同じ
- 🔴 **ブラウザを立ち上げておく必要はない**。Playwright が毎回ヘッドレスで自前のブラウザを起動し、
  `.tradingview-session` の保存済みログインを使う。**ふだんのChromeとは別物**。
  必要なのは「PCが起動していてWindowsにサインインしていること」だけ
- 🔵 **休場日は撮らない**（スクリプト側で `marketStatus` を見て終了する）。
  カレンダー判定は判断側と同じ単一情報源

🔴 **インジケーターを足すなら入れすぎないこと**（AIが読む前提）。BB(20,2)＋出来高くらいが上限で、
移動平均を何本も重ねると線とローソクが潰れて判断材料にならない。
🔵 そもそも**25/75/200日線と乖離・高安・ATR・トレンドは数値で渡してある**ので、
画像に足しても情報は増えない。画像の役目は**数値で表せないもの**（形・パターン・節目・出来高との関係）。

**② 売買した日だけ、保有画面を Chatwork に投げる**

松井証券の**保有株式（残高照会）**をスクショして、通知と同じルームに投稿するだけ。
🔵 取引履歴の画面ではなく、**いま何を何口持っているか**の画面。

🔴 **ファイル名に `chart` `tv` `tradingview` `チャート` を含めないこと。**
含むとチャート画像として扱われる。証券アプリのキャプチャは
`IMG_1234.jpg` のような既定の名前のままで問題ない。

🔵 **売買していない日は投げなくてよい。** 投げなければ同期は起きず、ロボ口座はそのまま。
🔵 個別株を持っていても構わない。対象4銘柄（1321 / 1570 / 1571 / 1357）以外は無視される。

### 自動でやること（翌営業日 08:30）

```
0. 東証が開いている日か確認する（休場なら何もせず終了）
1. 需給データの取得（従来どおり）
2. Chatwork から直近の画像を拾う（チャート・保有画面）
3. 保有画面を読み取って real_position.json に保存
4. 価格・需給・イベント・対照群の判断をまとめてAIに渡す
5. AIが判断（open / close / hold）
6. 損切り値を機械的に決めて口座に反映
7. robo_account.json と robo_logs/{日付}.json を保存
8. Chatwork に通知
```

### 通知の読み方

```
【ロボ口座】ブル2倍（1570 日経レバレッジ）を 30口 新規建て
確信度: 65%

■ 理由
（価格をどう読んだか。対照群と違う判断なら、その理由も）

■ この判断が外れるとき          ← 🔴 ここを必ず読む
（ロボ自身が挙げた負け筋）

■ あなたの保有の変化（前回のキャプチャから）
ブル2倍（1570）30口 を手仕舞い、ベア2倍（1357）を 320口 建てた（乗り換え）

■ 決定論ルール（対照群）: ブル
■ 口座 / ■ 成績（ロボ vs 対照群）
```

🔵 「あなたの保有の変化」は、**買い増し・減らした・新規・全部手仕舞い・乗り換え**を
判別して出す。前回のキャプチャから何がどう動いたかが一目で分かる。

🔴 **「この判断が外れるとき」を毎回読むこと。** ここに書かれた条件が実際に起きたら、
ロボの読みは外れている。鵜呑みにしないための仕掛けとして必須項目にしてある。

🔵 **hold（見送り）の日も毎日届く。** 半分以上の日は持たないのが、この戦略の正常な姿。

🔴 **ただし土日・祝日・年末年始（東証の休場日）は通知が来ない。** これは故障ではなく仕様。
休場日に「本日は hold」と流すと、**判断した日と何もしなかった日が混ざって成績の分母が狂う**ため、
ロボは休場日には判断そのものをしない。営業日かどうかは**ぽいロボのカレンダーと同じ判定**を使っている。

🔵 **FOMC・日銀・CPI などのイベントは、今後5営業日ぶんが判断材料としてAIに渡っている。**
カレンダー画面に出ているものと同じ表を見ているので、別途あなたが伝える必要はない。

## 2. 週の流れ

| いつ | 何を |
|---|---|
| 平日 | 上記の1日の流れ |
| 土曜 09:00（自動） | 週次データ・バックテストの再計算 |
| 週末（あなた） | エンジン画面でロボの成績を見る（勝率ではなく**期待値と最大DD**） |

### 成績の見方

画面（エンジンタブの右側・管理者のみ表示）に、ロボと対照群が並んで出る。

| | 勝率 | 期待値 | 最大DD |
|---|---|---|---|
| ロボ（AI） | … | … | … |
| 対照群（決定論） | … | … | … |

🔴 **勝率で判断しないこと。** 過去の実測で勝率は34〜40%が正常だと分かっている
（勝ちが大きく負けが小さいトレンドフォロー型のため）。見るのは**期待値と最大DD**。

🔴 **対照群より上かどうかが本丸。** リターンの絶対値ではない。
20年の検証では「日経2倍を持ちっぱなし」のほうが CAGR は高く（9.89% vs 9.23%）、
決定論ルールの価値は**ドローダウンを −88% から −42% に半減させたこと**にあった。
ロボにも同じ物差しを当てる。

## 3. うまくいかないときの挙動（すべて設計済み・慌てなくてよい）

| 起きたこと | どうなるか |
|---|---|
| PCが落ちていてチャートを撮れなかった | 数値だけで判断が動く。通知に「チャート画像なし」と出る |
| 売買していないので保有画面を投げなかった | 同期は起きない。ロボ口座はそのまま。判断は通常どおり動く |
| 同じ画像がChatworkに残っている | file_id で判定して**二度目の同期はしない** |
| 保有画面が読み取れなかった | 読めなかった項目を列挙して通知に出す。**推測では埋めない**。同期は見送り |
| 🔴 読み取りの数字が価格と合わない（桁誤りなど） | 実際の現在値と突き合わせて**弾く**。同期は見送り、通知に理由が出る |
| 🔴 対象4銘柄を2つ以上持っていた | どちらに合わせるか決められないので**同期しない**。通知で知らせる |
| 個別株など対象外の銘柄を持っている | 無視される。ロボ口座には写らない |
| 誤読でロボ口座がずれた | **次のキャプチャで自然に上書きされる**（累積しない）。同期由来の売買は成績にも入らない |
| AIが判断を返さなかった（拒否・エラー） | その日は **hold として記録**。🔴 決定論の結果では埋めない（判断器を混ぜないため） |
| AIが変な判断を出した（open なのに銘柄なし等） | 機械的に補正して通知に「判断の補正」と出す |
| AIが資金を超える数量を出した | 資金の上限で切り詰める |
| AIが逆方向を建てようとした（建玉あり） | 「決済 → 新規」に自動で分解する（同時保有は起きない） |
| Chatwork や API の鍵が未設定／クレジット切れ | 判断ステップだけ飛ぶ。**他のデータ更新は通常どおり動く** |

## 4. 触ってはいけないもの

- 🔴 `public/data/robo_account.json` — ロボの口座。手で直さない（実態に合わせるのはキャプチャで）
- 🔴 `public/data/robo_logs/` — 判断の記録。再現できない判断器の唯一の証拠
- 🔴 `src/utils/robotStrategy.mjs` — 対照群と損切りの式。変えると過去の成績と比較できなくなる
- 🔴 `.tradingview-session/` — ログイン情報。コミットしない（`.gitignore` 済み）

## 4.5 画面（エンジンタブ）

3カラム。**画面内（100vh）に収まる**ようにしてあり、スクロールするのは約定履歴だけ。

| 位置 | ブロック | 中身 |
|---|---|---|
| 左 | 上部 | 評価額 / 累計損益 / 現金 ＋ 判断器（モデル・effort）と更新時刻 |
| 左 | POSITION | 建玉（銘柄・数量・平均取得・損切り）＋ **LAST SYNC＝あなたの保有の変化**（前回のキャプチャから何がどう動いたか） |
| 左 | EQUITY CURVE | 資産推移 |
| 中 | PERFORMANCE | ロボ vs 対照群（勝率・期待値・最大DD）＋ 判定30件までの進捗バー |
| 中 | 🆕 YOUR CALL | **AIに従った時 vs 自分で外した時**の平均リターン・勝率・回数＋区間ごとの内訳 |
| 右 | TRADE LOG | 約定履歴（理由・**外れる条件**・確信度つき） |

🆕 **YOUR CALL の読み方。** PERFORMANCE が「AI は決定論ルールより上手いか」を測るのに対し、
YOUR CALL は**あなたの介入が効いているか**を測る。同期から次の同期までを1区間として、
その区間の頭で AI の判断どおりだったか／外したかで振り分け、区間リターンを比べている。
🔴 **4区間に満たないうちは数字を信用しない**（画面にも「数回では判断できません」と出る）。

🔵 需給を見る道具（環境 / 現物 / 先物 / 周期）は**シールドタブ**にある。エンジンタブはロボ口座1枚。

🔵 変えてよいのは**プロンプト**（`scripts/roboPrompt.mjs`）。
ただし変えたら判断器が変わったものとして、成績を分けて数え直す必要がある。

## 5. 30トレード貯まったら（Go / No-Go）

週次シグナルなら**約7ヶ月先**。焦って途中で判断しない。

| | 条件 |
|---|---|
| **続ける** | 期待値がプラス ／ 期待値が対照群以上 ／ 最大DDが対照群より浅い（同等まで可） |
| **やめる** | 期待値がマイナス、または対照群に明確に負けている（期待値もDDも下） |
| 早期打ち切り | 15件の時点で期待値が大きくマイナス |

🔵 やめる判断になっても、それは失敗ではない。
**「LLMに任せても決定論ルールを超えない」と分かること自体が成果**で、
そのために身銭を切らずに7ヶ月測る仕組みにしてある。

## 6. コスト

| | 見積もり |
|---|---|
| 1回の判断 | 約50円（`claude-opus-5` / effort `high`） |
| 1ヶ月（営業日20日・1日1回） | **約1,000円** |

🔵 高いと感じたら `effort` を `medium` に下げる（概ね半額）。
🔴 ただし effort を変えたら判断器が変わったものとして、成績を分けて数え直す。
🔴 プロンプトキャッシュは効かない（実行間隔が24時間で、キャッシュの寿命は最大1時間のため）。
