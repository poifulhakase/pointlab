# 一時トークルームの新着を LINE に通知する（設定手順）

> 🔴 **ぽいロボ本体とは無関係の間借り機能**。使い終わったら片付ける（最後の節）。
> コードは入っているが、**環境変数を入れるまで何も起きない**（通知は黙って捨てられる）。

## これは何か

トークルームに新着が出たとき、LINE の公式アカウントから**「新着があります」を1通push**する。
相手のロック画面に出るので、**LINEが使えなくても通知だけで気づける**。

```
新着 → 送った側のブラウザ → /api/talk?a=notify → LINE → 相手のロック画面
```

- 🔵 **相手が画面を開いている間は送らない**（在席が分かるため。会話中に鳴りっぱなしにならない）
- 🔵 連投は**最短90秒に1通**へまとめる。1日60通が上限（どちらも環境変数で変えられる）
- 🔴 送り先は**サーバーの環境変数で固定**。外から宛先は指定できない

## ユーザー作業（3つ）

### ① LINE公式アカウントを作り、トークンを発行する

1. https://developers.line.biz/console/ → プロバイダーを作る（名前は何でもよい）
2. 「Messaging API」チャネルを作る
3. **Messaging API設定** タブ →「チャネルアクセストークン（長期）」を発行してコピー
4. 同じ画面の **「グループトーク・複数人トークへの参加を許可する」を ON**（既定はOFF）
   🔴 ここがOFFだと、Botをグループに入れても即退出してしまう
5. 「応答メッセージ」は OFF でよい（自動返信が要らないため）

### ② 送り先ID（グループなら `C…`）を調べる

1. LINE Developers の **Messaging API設定 → Webhook URL** に
   `https://pointlab.vercel.app/api/talk?a=webhook` を入れて「Webhookの利用」を ON
2. Vercel に `LINE_CHANNEL_ACCESS_TOKEN` を入れて再デプロイ（ここまでで webhook が動く）
3. **Botをグループに招待する**（1対1で使うなら、友だち追加して「id」とだけ送る）
4. Bot が **「この場所のID（グループ） C…」** と返してくるので、その値を控える
5. 控えたら **Webhookは切ってよい**（通知の送信には使わない）

🔴 **相手が既に入っているグループにBotを入れる**のが一番よい。相手の操作が要らない。
🔴 そのグループに**他の人がいると全員に通知が飛ぶ**。2人だけのグループを使うこと。

### ③ Vercel に環境変数を入れる

| 変数 | 中身 |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | ①で発行したトークン |
| `LINE_TARGET_ID` | ②で調べたID（`C…` / `U…`） |
| `TALK_ROOM_ID` | トークルームの部屋ID（32桁の16進。`firestore.rules` にある値） |
| `TALK_NOTIFY_BODY` | `off` にすると本文を載せず「新着があります」だけにする（既定は載せる） |
| `TALK_NOTIFY_MIN_SEC` | 最短間隔の秒数（既定 90） |
| `TALK_NOTIFY_MAX_PER_DAY` | 1日の上限（既定 60） |

🔴 **`echo` で入れない**（末尾の改行が付いてヘッダーエラーになる）。
　 `node -e "process.stdout.write('...')"` を使うか、Vercel の画面から貼る。

入れたら再デプロイ。トークルームで送って、相手側のLINEに届けば完了。

## おまけ：トークの中でAIに聞く（左下の🤖）

同じ `api/talk.js` に相乗りしている（`?a=ai`）。Web検索つきで、店や周辺情報を調べて短く答える。

| 変数 | 中身 |
|---|---|
| `ANTHROPIC_API_KEY` | ぽいロボの疑似トレードと**同じ残高**を使う。新しく発行してもよい |
| `ANTHROPIC_WORKSPACE_ID` | 🔴 **いま Console で作る鍵（アカウント紐付け型）では必須**。`wrkspc_...` |

🔴 **鍵を新しく作ると、ワークスペースIDのヘッダーが要る**。無いと全部これで落ちる:
```
400 anthropic-workspace-id is required when authenticating with an identity-linked API key
```
疑似トレードの古い鍵（「ワークスペース（レガシー）」型）は不要なので、この落とし穴は今回が初出。
IDの調べ方＝Console → 組織の設定 → ワークスペース → 対象を開き、URL の `wrkspc_...` を取る。

- 🔴 **未設定だと「AIはまだ使えません」と出るだけ**（他の機能には影響しない）
- 質問も答えも**そのままトークに流れる**（2人とも読める）
- モデル `claude-opus-5` / effort `low` / 検索は1回の質問につき最大4回。**1回あたり十数円**が目安
- 制限＝1分に3回・1日40回（`_ratelimit.js` を再利用）
- 🔴 答えの長さは `AI_SYSTEM`（`api/_talkNotify.js`）で縛っている（5行以内・候補は3件まで）。
  緩めると画面が読めなくなるので、テストで固定してある

## 動かないときの見どころ

| 症状 | 見るところ |
|---|---|
| 何も届かない | 環境変数が3つとも入っているか（1つでも欠けると**黙って何もしない**仕様） |
| 403 が返る | `TALK_ROOM_ID` が実際の部屋IDと違う |
| 502 が返る | トークンが切れている／`LINE_TARGET_ID` の形が違う |
| Botがグループから消える | ①-4 の「グループトークへの参加を許可」がOFF |
| 届く数が足りない | 最短90秒にまとめている（`TALK_NOTIFY_MIN_SEC`）。相手が開いている間は送らない |

🔵 無料枠は月200通程度。2人のやり取りなら、まとめ送りで収まる見込み。

## 片付け

1. Vercel の環境変数4つを消す（これだけで通知は止まる）
2. `api/talk.js` / `api/_talkNotify.js` を削除
3. `src/utils/talkRoom.ts` の `notifyPeer` と、`TalkRoom.tsx` の呼び出しを削除
4. `vercel.json` の `functions` から `api/talk.js` の行を削除
5. LINE公式アカウントを削除（残しても害はない）
