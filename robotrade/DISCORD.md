# ぽいんとらぼ Discord 設計書

日本株スイングトレード疑似マシン（`SPEC.md`）の**通知・観察環境**としての Discord 側の設計。
マシン本体の実装仕様は `SPEC.md`、こちらは**見た目・チャンネル・通知フォーマット・運用**を扱う。

> **世界観上の位置づけ**: ぽいロボは「**未来ガジェット（ぽいふる博士の発明品）**」の一つ。
> 「**株式トレード研究室**」（テクニカル・需給・イベントドリブンの研究録）で研究した手法を、
> 実際に動かして試す**実験的ツール**。勝つためでなく、体験・観察するための発明品。
> 登場: ぽいふる博士（主任研究員＝運用者本人）／ぽいロボ（発明品＝通知の主役）／ぽよん君（助手・読者の代弁者＝添え役）。

> 大原則（SPEC 11章より）: **Discord＝プッシュ（一目で見る）／ダッシュボード＝プル（じっくり見返す）**。
> 各チャンネルとも「**要点だけ**」。生ログは流さない（ノイズで見なくなる）。詳細はダッシュボードと `logs/`。

実装: `robotrade/notify/{discord,summary,chart}.py` ／ 設定: `config.yaml` の `discord:` ／
Webhook URL: `.env`（チャンネルごとに別々）。テスト: `tests/test_notify.py`。

## 1. サーバー / チャンネル構成

サーバー: **ぽいんとらぼ**／ Bot キャラ: **ぽいふる博士**

| チャンネル | 頻度 | 役割 | `.env` のキー |
|-----------|------|------|-------------------|
| **#判断サマリ** | 日次・引け後 | 翌営業日の想定売買（メインの一目） | `DISCORD_WEBHOOK_DECISIONS` |
| **#約定・保有** | 日次・引け後 | 今日の約定＋保有一覧（何が動いたか） | `DISCORD_WEBHOOK_FILLS` |
| **#成績** | 週次（既定=金曜） | 総資産・勝率・期待値・DD・TOPIX比＋グラフ | `DISCORD_WEBHOOK_PERFORMANCE` |
| **#エラー・異常** | イベント時のみ | 障害・リスクオフ・コストアラート（赤） | `DISCORD_WEBHOOK_ERRORS` |

- 各チャンネルは**別々の Webhook**を発行して振り分ける。
- 🔴 **Webhook URL は config.yaml に書かない**（知っていれば誰でも投稿できる＝実質パスワード）。
  `config.yaml` は env 変数名だけを持ち、値は `.env` から引く。
- 🔴 **異常を日次の一目に混ぜない**。`errors` が未設定でも他チャンネルに寄せず、ログに残すだけ。
- 疎通確認: `main.py --notify-test`（4チャンネルに1通ずつ）。
- 🔴 **送信したら message_id を必ず記録する**（`logs/sent_messages.jsonl`）。
  Webhook は**自分の投稿を一覧できない**（読み取り権限が無い）ので、
  削除に要る message_id は**送った瞬間に残しておくしかない**。
  そのため送信は `?wait=true` で行い、返ってきた id を記録している。
  記録が無い投稿は Discord の画面から手で消すしかない。
- 後片付け: `main.py --purge-test`（疎通確認だけ）／`--purge-all`（記録してある全部）／
  `--purge-dry-run`（消さずに件数だけ）。消せなかったものは記録に残す（取りこぼしを見失わない）。

## 2. 通知キャラクター（顔）

登場人物（`pointlab` の世界観）:
- **ぽいふる博士** = 人間・サーバー管理者（＝運用者本人）。通知の送信者にはしない。
- **ぽいロボ** = アプリ／システムの顔。**メインの通知係**。無機質で正確、淡々と事実を報告する。
- **ぽよん君** = 博士の助手・読者の代弁者（雲キャラ、のんびり照れ屋、口癖「ぼくにもできるかな？」）。**添え役**として人間に寄り添う一言を担当。

**役割分担の思想**: 「判断はマシン、観察するのは人間」という設計の二層構造を、そのまま2体に対応させる。**ぽいロボが事実を報告し（機械の正確さ）、ぽよん君が人間に寄り添う（人間味）**。ただし当面は**ぽいロボ主役**で立ち上げ、ぽよん君は「ここぞ」で登場する温度感（やりすぎない）。

| チャンネル | 送信者（`username`） | 基調色 |
|-----------|---------------------|--------|
| #判断サマリ | `ぽいロボ｜判断` | 青 `0x3498DB` |
| #約定・保有 | `ぽいロボ｜約定` | 緑 `0x2ECC71` |
| #成績 | `ぽいロボ｜成績`（節目で**ぽよん君**が一言添える） | 紫 `0x9B59B6` |
| #エラー・異常 | `ぽいロボ｜異常` | 赤 `0xE74C3C` |

- **アイコン**: Discord のアバターは**円形トリミング**。横長のフル版は丸で欠けるので、
  **正方形・顔中心**に切り出した版を `scripts/make_avatars.py` で生成してある。
  配信URL: `https://pointlab.vercel.app/calendar/discord/{poirobo,poyonkun}-avatar.png`
  （🔵 `/stock-calendar/...` は SPA の HTML が返るので使わない）
  Webhook 側のアバター設定に加えて、送信時 JSON の `avatar_url` でも指定している。
- **個別カードの色**: action 色（buy=緑 / sell=赤 / hold=グレー）が**カード単位で優先**。
  チャンネルの基調色は総括カードに使う。
- **ぽよん君が出る条件**（`poyon_milestone()`）:
  - トレード件数が節目（`discord.milestone_trades` = 10/30/50/100件）に到達
  - ドローダウンが `risk.drawdown_throttle`（10%）を超えた
  それ以外は**黙っている**。毎回は出さない。

## 3. 通知フォーマット（チャンネル別 embed）

### 3.1 #判断サマリ

**総括カード**（チャンネル基調色。リスクオフ時は橙）
- 地合い（売買判断AIの `market_view`）
- しぼり込み: `候補◯件 → 分析◯件 → 新規◯件 / 見送り◯件`
- リスクオフを検知していればその理由

**候補ごとのカード**（最大8枚・action 色）
- 見出し: `買い 6986.T 双葉電子工業【翌寄りで発注】`
- 水準: `入 806 / 損切 735 / 利確 880`・想定保有日数
- 確信度
- **各AIの読みを1行ずつ**（要点主義）:
  - 📈 チャート: regime（週足の向き）・勢い・位置・ブレイク出来高・スイング適性
  - ⚖️ 需給: スコア・売り圧力・踏み上げ余地・保有期間内のイベント
  - 📰 ニュース: 材料の方向・強さ・出所（未導入なら「データなし」と明記）
  - 🤖 予測ML: 確率（未導入なら「未導入」）
- 判断の理由（500字まで）
- 却下された場合は**こちらの処理**（ストップ妥当性ガード・上限・相関など）
- TradingView リンク

🔴 **数量は出さない**。数量は翌営業日の実際の寄り値からコードが逆算するので、
この時点では未確定。確定していない数字を出すと翌日の約定とズレて混乱する。

売買が1件も無い日は「今日は売買なし」のカードを出す（**無理にトレードしないのも判断のうち**）。

### 3.2 #約定・保有

- **約定**（前営業日の判断を今日の寄りで執行したぶん）: 銘柄・株数・約定価格・チャートリンク
- **手仕舞い**: 勝ちも負けも**同じ形・同じ重み**で並べる（確証バイアス対策・SPEC 12.1）。
  損益・理由・保有営業日数。
- **保有一覧**: 銘柄・株数・取得単価→現在値・**含み損益**・**保有 ◯/14日**・損切/利確水準

🔴 **含み損も必ず出す**（損失回避・サンクコスト対策。見たくないものから目を背けさせない）。
🔴 **総資産の増減率はここに出さない**（4章・日々のP&Lを煽らない）。
🔵 動きも保有も無い日は**送らない**（通知の静かさ）。

### 3.3 #成績（週次・既定は金曜）

**ここだけが総資産の増減を語ってよい場所。**

- 資産: 総資産（開始比%）・現金・建玉数・含み損益・最大ドローダウン
- **TOPIX比**: 自分% / TOPIX% / **超過%**（「地合いで勝っただけ」を見抜くため）
- 成績:
  - 件数（勝/負/時間切れ）・勝率と**95%信頼区間**
  - **期待値の分解**: `期待値 = 勝率 × 平均利益 − 敗率 × 平均損失`
  - ペイオフレシオ・平均保有営業日数
  - **保有日数別**の件数/勝率/平均損益（持ちすぎていないか）
- n < 30 のときは「**暫定値**。勝率でモデルやプロンプトをランク付けしない」と明記
- **直近の負けトレード**を常設（負けを埋もれさせない）
- **推移グラフ**を添付（下記）
- 節目なら**ぽよん君**が一言

**グラフ**（`robotrade/notify/chart.py`）
- 🔴 **二軸にしない**。総資産（円・数百万）と TOPIX（ポイント・数千）は桁が違うので、
  **両方を起点100に指数化して1本の軸**に載せる。二軸は目盛りの取り方でどちらが勝っている
  ようにも見せられる。
- 色は検証済みのペア（青 `#3987e5` / 橙 `#d95926`）。Discord の暗い背景で
  CVD 分離 ΔE 26.8・コントラスト3:1以上を満たすことを確認済み。
- 凡例に加えて**線の右端に直接ラベル**（色だけに意味を持たせない）。
- データ点が2つ未満のときは描かない。

### 3.4 #エラー・異常

`[種別] 見出し` ＋ 発生時刻 ・ **状態ラベル** ・ 内容。

| 種別 | いつ | 状態 |
|---|---|---|
| コスト | 1日のAPIコストが `ops.daily_cost_alert_usd` を超えた | 要対応 |
| リスクオフ | 市場急変を検知して新規を止めた | 自動復帰 |
| データ | 参照データが古い/欠けていて実行をスキップした | 要対応 |
| 休場 | 祝日・年末年始で走らせなかった | 自動復帰 |
| 障害 | パイプラインが落ちた | 要対応 |

🔵 状態は「要対応／自動復帰」の**ラベル**で示す。「ご確認ください」のような依頼文は書かない
（事実だけ伝える）。

## 4. 運用ルール

- **上限**: 1メッセージ 2000字／embed は10個・合計6000字・25フィールドまで。
  超える分は `send_batched()` が自動で分割する。フィールド値は1024字で切る。
- **要点主義**: 生ログは流さない。詳細は `logs/<日付>/` と `robotrade.db`。
- **バイアス対策（SPEC 12.1）**:
  - 成績は**週次でどっしり**。日々のP&Lを煽らない（総資産±%は #成績 だけ）。
  - 勝ちと負けを**均等に**表示。負けトレードを成績サマリに常設する。
  - AIの読みは**結果が出る前に**ログへ確定させ、後から結果を見て評価し直さない。
  - n が小さいうちは信頼区間を併記し、点推定を信じさせない。
- **通知の静かさ**: 日中はプッシュを増やさない。**引け後に1回**走らせるだけ。
  動きの無い日は #約定・保有 を送らない。#エラー・異常 はイベント時のみ。
- **免責**: 全チャンネルの embed footer に
  「※ 疑似トレードの実験であり投資助言ではありません」を入れる（SPEC 15 / 金商法）。

## 5. 将来拡張：Bot 化（今は不要）

- 現状は **Webhook（送信のみ）** で「通知メイン」の要件を満たす。常駐サーバー不要。
- 次を「したい」と思ったら Bot 化を検討（常駐が必要になり設計変更を伴う）:
  - スラッシュコマンド（`/残高` `/今日の判断` などこちらから問い合わせ）
  - ボタン・メニュー（通知に「詳細」ボタン等）
  - リアルタイム応答
- 判断基準: **見た目の作り込みは Webhook で足りる。対話が欲しくなったら Bot**。
