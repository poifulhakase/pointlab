# note 新着通知（おまけ機能）

トレードマシン（`SPEC.md` / `DISCORD.md`）とは**別系統のおまけ機能**。混ぜない。
note の新着記事を Discord の `#note新着` に流すだけの「お知らせ機能」。

実装: `robotrade/notify/feeds.py` ／ 設定: `config.yaml` の `feeds:` ／
Webhook: `.env` の `DISCORD_WEBHOOK_<チャンネル名を大文字>` ／ テスト: `tests/test_feeds.py`

キャラは**ぽよん君**（お得情報を一緒に探す助手）。ぽいロボはトレード側の顔。

Zapier は初回設定が面倒＆無料枠に制限があるので不採用。

## 🔴 依頼文から変えた2点

### 1. 「日次バッチの**最後**に足す」→ **スキップ判定より前**に置いた

トレードの日次バッチは**休場日・参照データが古い日にスキップして早期 return する**。
末尾に置くと、連休のあいだ note の新着が溜まったまま流れない。
（実際 2026-09-19〜23 は土日＋敬老の日＋国民の休日＋秋分の日で **5日連続の休場**）

→ 相乗りはするが、`main.py` の**トレード側スキップ判定より前**で独立して走らせる。
　 `--note-only` で note のチェックだけ走らせることもできる。

### 2. 重複防止は pubDate ではなく **guid の集合**

記事は後から編集・バックデートされることがある。「最後の pubDate より新しいもの」方式だと
取りこぼしや二重投稿が起きる。見た guid を覚えるほうが素直で確実
（`feed_state.json`・情報源ごとに直近1000件）。

### 3. ポイ活は **1日1記事**（運用者の指示・2026-09-19）

ポイ探は実測**1日10件**。1件1メッセージだと毎日10通になり、
DISCORD.md 4章の「通知の静かさ」に反する。

→ **公開時刻がいちばん新しい1件だけ**をカード（サムネ付き）で出し、
　 **残りは既読にして捨てる**（`card_limit: 1` ＋ `drop_rest: true`）。

🔴 **捨てずに持ち越さない**。持ち越すと毎日9件ずつ未読が積み上がり、
　 永久に追いつかないまま古い記事を流し続けることになる。
🔴 **捨てた件数は本文に出す**（「新着10件のうち、いちばん新しい1件。」）。
　 黙って消すと「今日は1件しか無かった」と誤解する。

🔵 note は**全件通知**（運用者の指示）。低頻度なので1件1メッセージのまま。

## 動き

```
RSS取得 → 古い順に並べ直す → 既読(guid)を引く → 増えたぶんだけ投稿 → 既読に足す
```

### 出し方（`style`）

| style | 使うとき | 形 |
|---|---|---|
| `per_item` | 低頻度（note） | 1件1メッセージ `📝 新着｜{title}｜by {creator}｜{link}` |
| `cards` | 流量が多い（ポイ活） | 1メッセージ＝見出し＋**上位 `card_limit` 件のカード** |
| `digest` | 一覧だけでよいとき | 1メッセージ＝見出し＋一覧行のみ |

`drop_rest: true` … カードに載らなかったぶんを**既読にして捨てる**（持ち越さない）。
`drop_rest: false` … 載らなかったぶんを同じメッセージの「そのほか」一覧に出す。

🔵 同じチャンネルに複数の情報源がある場合、`style` / `card_limit` / `drop_rest` は
**揃っていないと起動時にエラー**にする（どのソースの設定でまとめるかが決まらないため）。

**カード**: 見出しが記事リンク／説明文は本文の冒頭（HTMLと定型句を除去）／
右にサムネ／フッターに「情報源 ｜ by 著者 ｜ カテゴリ」。

🔴 **「上位」は公開時刻の新しい順**。お得情報は鮮度が価値なので古いものをカードにしない。
情報源ごとに固めて並べると、今日の記事が一覧に落ちてしまうので**ソースをまたいで**並べる。

🔴 Discord の制限に収める: embed は1メッセージ10個まで（見出し1＋カード最大8＋一覧1）。
1フィールドは1024字までなので、一覧が溢れたら「（つづき）」のフィールドへ送る
（超えると**黙って切れる**）。

### 事故を防ぐための決め

| 場面 | どうするか | なぜ |
|---|---|---|
| **初回実行** | 投稿せず、全件を既読にするだけ | 導入した瞬間に25件でチャンネルが埋まる |
| **RSSが0件** | 既読をいじらず「取得失敗の可能性」として終わる | ここで保存すると既読が消え、次回に全件投稿してしまう |
| **既読ファイルが壊れている** | 例外を投げて止める（初回扱いにしない） | 初回扱いにすると既読が消えて全件投稿になる |
| **投稿に失敗** | そこで止め、失敗したぶんは既読にしない | 次回もう一度出す |
| **新着が多い** | `max_per_run`（ポイ探は30件）まで拾い、そこから `card_limit` 件を出す | 一気に流さない |
| **捨てたのに「新着なし」** | 「N件は既読にして流さず」とログに出す | 新着はあった、が事実 |
| **サムネが無い** | サムネ無しのカードにする | 無い画像をでっち上げない |

## SNS への自動投稿（Buffer 経由・2026-09-20／Threads 追加 2026-09-21）

共同マガジン「普通じゃない副業図鑑」の新着を、**1日1件**だけ X（@Aojiru_Hakase）へ予約する。
実装は `robotrade/notify/{buffer,x_compose,x_runner}.py`、設定は `config.yaml` の `buffer:` / `x_post:`。

### なぜ X API を直接使わないか

| | |
|---|---|
| X API | 2026年2月に**無料枠が廃止**、4月から**リンク付き投稿は1件 $0.20**。実測 月83件で **$16.6/月** |
| Zapier / Make | 2026年2月に X 連携が復活したが**自分の X アプリを繋ぐ方式**＝従量課金は自分持ち。解決にならない |
| **Buffer** | ✅ X API の費用を**自分で払わなくてよい**。無料プランで API キーを発行でき、投稿・削除まで実測で通った |

AI の一言は Haiku 4.5 で **1件 $0.0025**（月10円ほど）。費用の主因は X API 側だったので、
Buffer に替えたことで**一言を付けても実質ゼロ円**になった。

### 守っていること

- 🔴 **1日1件**。残りは既読にして捨てる（持ち越すと毎日2件ずつ積み上がって追いつかない）。
- 🔴 **既読は Discord と別に持つ**（`x:<source_key>`）。Discord は全件、X は1日1件なので集合が違う。
- 🔴 **初回は投稿しない**。導入直後にタイムラインを埋めない（実際そうなった）。
- 🔴 **翌朝9時に予約**する。夕方の実行からそのまま出すと夜中に流れる。
  🔵 副作用として、**出る前に Buffer のキューから消せる**（十数時間の猶予）。
- 🔴 Buffer 無料プランは**1チャンネル予約10件まで**。1日1件ならぶつからない。

### 文面と人格

形は @Aojiru_Hakase の実際の投稿に合わせた（**一人称・絵文字なし・書き手を `｜` で添える**）。
文体は welcomebot の `greeting.py` と同じ人格（〜じゃ / 〜かもしれん / 諸君）。

🔴 **運用者はマガジンの運営者であって、記事の書き手ではない**（2026-09-20 の指摘）。
そのため一言は「こんな記事が届いた」という**紹介にとどめる**:

- 評価しない（良い/悪い・正しい/間違い・おすすめを言わない）
- 断定しない。`稼げ・儲か・必ず・絶対・確実・保証・おすすめ・すべき・ぜひ` が入ったら
  **一言そのものを捨てて**紹介だけ出す（`is_safe()`。プロンプトだけに頼らずコードでも止める）
- 書き手の人物評を書かない
- 🔴 **固定ハッシュタグを置かない**。マガジンには副業と無関係な記事（AIの技術記事など）も
  届くので、毎回 #副業 を貼ると中身と食い違う。タグは候補から AI が選び、
  **候補の外は捨てる**（`pick_hashtags()`）。

### 鍵

`.env` の `BUFFER_API_KEY`。🔴 **有効期限がある**（発行時に選ぶ）。切れると投稿が黙って止まるので、
`config.yaml` の `buffer.key_expires` に控えてある。権限は `account:read` / `posts:read` / `posts:write` だけ。


### Threads を足した（2026-09-21）

設定を `x_post:` → **`sns_post:`** に作り直し、`targets` に宛先を並べる形にした。
X（`Aojiru_Hakase`）と Threads（`poifulhakase`）の2つ。Buffer 無料プランは3チャンネルまで。

| | X | Threads |
|---|---|---|
| 上限 | 280（**日本語は1文字2**＝実質140） | 500（日本語も1文字1） |
| 一言 | 2〜3行・50字 | 4〜6行・150字 |
| タグ | 最大3個 | 1個（タグ文化が薄い） |
| 予約 | 翌 9:00 | 翌 12:00 |

🔴 **文面は宛先ごとに別々に書かせる**。同じ文を両方に流すと、どこで見ても同じで読む理由が
なくなるうえ、スパム的な使い方に近づく。字数も違うので、そもそも同じ文では収まらない。
🔵 費用は Haiku の呼び出しが1件増えるだけ（2宛先で1日 $0.0055＝月17円ほど）。
🔵 既読は**宛先ごとに分けない**（同じ記事を両方に出したいので1つで持つ）。

**実物を出して分かったこと（2件）**

1. 🔴 **note の表示名はプロフィール文のことがある**
   （「ハル ｜基本フォロバ100 | note×AIで資産型コンテンツの作り方発信中」）。
   そのまま載せたら X が **280/280** になり、一言の余地が消えた。
   区切り記号で切って16字に詰める（`shorten_credit`）。🔴 **名前は必ず残す**（他人の記事なので）。
2. 🔴 **禁止語「べき」が、ふつうの問いかけを巻き込んでいた**。
   「見つめ直す**べき**か」が「〜すべきだ」に当たって一言が丸ごと落ちた。
   単語ではなく**言い切っている形**（`すべきだ` `べきだろう`）を正規表現で弾くよう直した。
