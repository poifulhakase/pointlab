# note 新着通知（おまけ機能）

トレードマシン（`SPEC.md` / `DISCORD.md`）とは**別系統のおまけ機能**。混ぜない。
note の新着記事を Discord の `#note新着` に流すだけの「お知らせ機能」。

実装: `swinglab/notify/feeds.py` ／ 設定: `config.yaml` の `feeds:` ／
Webhook: `.env` の `DISCORD_WEBHOOK_<チャンネル名を大文字>` ／ テスト: `tests/test_feeds.py`

キャラは**ぽよん君**（お得情報を一緒に探す助手）。ぽいロボはトレード側の顔。

---

## 方針（Zapier は使わない）

Zapier は初回設定が面倒＆無料枠に制限があるので不採用。
**既存の日次バッチに相乗りさせる**のが構成的に自然（外部サービス不要・コスト0）。

### feedparser でのキー名:

| ほしいもの | feedparser のキー |
|---|---|
| 記事名 | `title` |
| URL | `link`（`id` も同じ値） |
| 公開日時 | `published` / `published_parsed` |
| 投稿者名 | **`note_creatorname`**（名前空間つき要素が正規化される） |
| サムネ | **情報源ごとに違う**（下記） |

## 🔴 依頼文から変えた2点

### 1. 「日次バッチの**最後**に足す」→ **スキップ判定より前**に置いた

トレードの日次バッチは**休場日・参照データが古い日にスキップして早期 return する**。
末尾に置くと、連休のあいだ note の新着が溜まったまま流れない。
（実際 2026-09-19〜23 は土日＋敬老の日＋国民の休日＋秋分の日で **5日連続の休場**）

→ 相乗りはするが、`main.py` の**トレード側スキップ判定より前**で独立して走らせる。
　 `--note-only` で note のチェックだけ走らせることもできる。

### 2. 重複防止は pubDate ではなく **guid の集合**

記事は後から編集・バックデートされることがある。「最後の pubDate より新しいもの」方式だと
取りこぼしや二重投稿が起きる。見た guid を覚えるほうが素直で確実
（`feed_state.json`・情報源ごとに直近1000件）。

### 3. ポイ活は **1日1記事**（運用者の指示・2026-09-19）

ポイ探は実測**1日10件**。1件1メッセージだと毎日10通になり、
DISCORD.md 4章の「通知の静かさ」に反する。

→ **公開時刻がいちばん新しい1件だけ**をカード（サムネ付き）で出し、
　 **残りは既読にして捨てる**（`card_limit: 1` ＋ `drop_rest: true`）。

🔴 **捨てずに持ち越さない**。持ち越すと毎日9件ずつ未読が積み上がり、
　 永久に追いつかないまま古い記事を流し続けることになる。
🔴 **捨てた件数は本文に出す**（「新着10件のうち、いちばん新しい1件。」）。
　 黙って消すと「今日は1件しか無かった」と誤解する。

🔵 note は**全件通知**（運用者の指示）。低頻度なので1件1メッセージのまま。

## 動き

```
RSS取得 → 古い順に並べ直す → 既読(guid)を引く → 増えたぶんだけ投稿 → 既読に足す
```

### 出し方（`style`）

| style | 使うとき | 形 |
|---|---|---|
| `per_item` | 低頻度（note） | 1件1メッセージ `📝 新着｜{title}｜by {creator}｜{link}` |
| `cards` | 流量が多い（ポイ活） | 1メッセージ＝見出し＋**上位 `card_limit` 件のカード** |
| `digest` | 一覧だけでよいとき | 1メッセージ＝見出し＋一覧行のみ |

`drop_rest: true` … カードに載らなかったぶんを**既読にして捨てる**（持ち越さない）。
`drop_rest: false` … 載らなかったぶんを同じメッセージの「そのほか」一覧に出す。

🔵 同じチャンネルに複数の情報源がある場合、`style` / `card_limit` / `drop_rest` は
**揃っていないと起動時にエラー**にする（どのソースの設定でまとめるかが決まらないため）。

**カード**: 見出しが記事リンク／説明文は本文の冒頭（HTMLと定型句を除去）／
右にサムネ／フッターに「情報源 ｜ by 著者 ｜ カテゴリ」。

🔴 **「上位」は公開時刻の新しい順**。お得情報は鮮度が価値なので古いものをカードにしない。
情報源ごとに固めて並べると、今日の記事が一覧に落ちてしまうので**ソースをまたいで**並べる。

🔴 Discord の制限に収める: embed は1メッセージ10個まで（見出し1＋カード最大8＋一覧1）。
1フィールドは1024字までなので、一覧が溢れたら「（つづき）」のフィールドへ送る
（超えると**黙って切れる**）。

### 事故を防ぐための決め

| 場面 | どうするか | なぜ |
|---|---|---|
| **初回実行** | 投稿せず、全件を既読にするだけ | 導入した瞬間に25件でチャンネルが埋まる |
| **RSSが0件** | 既読をいじらず「取得失敗の可能性」として終わる | ここで保存すると既読が消え、次回に全件投稿してしまう |
| **既読ファイルが壊れている** | 例外を投げて止める（初回扱いにしない） | 初回扱いにすると既読が消えて全件投稿になる |
| **投稿に失敗** | そこで止め、失敗したぶんは既読にしない | 次回もう一度出す |
| **新着が多い** | `max_per_run`（ポイ探は30件）まで拾い、そこから `card_limit` 件を出す | 一気に流さない |
| **捨てたのに「新着なし」** | 「N件は既読にして流さず」とログに出す | 新着はあった、が事実 |
| **サムネが無い** | サムネ無しのカードにする | 無い画像をでっち上げない |

## 使い方

```powershell
Set-Location 'C:\Project\PointLab\stock-calendar\swing-lab'

.\.venv\Scripts\python.exe main.py --feeds-only            # フィードのチェックだけ
.\.venv\Scripts\python.exe main.py --feeds-only --dry-run  # 投稿せず件数だけ見る
.\.venv\Scripts\python.exe main.py --no-feeds              # 飛ばしてトレードだけ
.\.venv\Scripts\python.exe main.py                         # 通常（フィード → トレードの順）
```

投稿は `logs/sent_messages.jsonl` に記録されるので、`main.py --purge-all` で消せる。
